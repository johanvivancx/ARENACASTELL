# Puntos de la rúbrica

Esta guía relaciona los requisitos del Proyecto Integrador con los archivos de Arena Castell. El proyecto lo desarrolla **Johan Vivanco de forma individual**. Los puntos de la tabla son los máximos de cada criterio, no una nota obtenida.

| Criterio | Puntos | Dónde se puede revisar |
|---|---:|---|
| BD 1.1: modelo y normalización | 3 | Diagrama de tablas, claves primarias y foráneas; explicación en ARQUITECTURA.md. |
| BD 1.2: validaciones y reglas | 3 | CHECK, DEFAULT, UNIQUE, función de cédula, triggers y procedimiento de mensualidad. |
| BD 1.4: reportes con varias tablas | 2 | Vistas de pagos, mensualidades y ocupación. |
| BD 1.5: seguridad y respaldos | 2 | Permisos de acceso, contraseñas protegidas y guía de copia y restauración. |
| Frontend 2.1: diseño adaptable y mensajes | 4 | HTML y CSS, menú móvil, formularios y mensajes de error. |
| Frontend 2.3: funcionamiento | 3 | Recorridos de reserva, torneo y escuela, con historial y comprobantes. |
| Frontend 2.4: uso de Git | 3 | Repositorio, ramas y commits con los avances del proyecto. Ver la nota de entrega individual. |
| POO 3.1: diagrama de clases | 3 | Diagrama de Usuario, sus tipos y las clases de servicios. |
| POO 3.2: clases en funcionamiento | 2 | Las clases participan en los cálculos y permisos del sistema. |
| POO 3.3: principios de POO | 3 | Abstracción, encapsulamiento, herencia, polimorfismo y separación del código. |
| POO 3.4: organización | 2 | Archivos separados para servidor, servicios, clases, base y pruebas. |

La aplicación tiene un máximo de 30 puntos. La exposición tiene 20 puntos: propuesta, funcionamiento, claridad al explicar y justificación del código y el diseño.

## Entrega individual

La rúbrica original incluye un criterio de trabajo en equipo con Git. Como esta entrega es individual, su forma de evaluación debe aclararse con el docente.

La rúbrica pide POO, pero no obliga a usar Flask. En este proyecto se usa Python con su servidor estándar para conectar los HTML con PostgreSQL.

## Antes de entregar

- Terminar la conexión de la base y comprobar los tres servicios.
- Revisar que las tarifas y horarios sean los que corresponden.
- Probar la página en celular y con teclado.
- Revisar la configuración del correo sin mostrar claves.
- Preparar la explicación de las clases, triggers, procedimiento y vistas.

El documento de Diseño Universal se usa como referencia para el diseño. Sus actividades individuales, prácticas y grupales no forman parte de esta entrega.
